Политика конфиденциальности

Эта политика относится к Obsidian KMV Assistant, личному локальному инструменту синхронизации задач с Google Календарём. Инструмент управляется владельцем аккаунта GitHub kmvcalm-cloud и предназначен для его собственного использования.

1. Какие данные используются

  • Локальные задачи, отмеченные для календарной синхронизации: название, дата, время, длительность и служебный идентификатор/ссылка на исходную задачу.
  • Данные Google Calendar, необходимые для сопоставления и обновления связанных событий: идентификаторы, название, описание, начало и окончание события.
  • OAuth-токены, позволяющие выполнять разрешённую синхронизацию без повторного входа при каждом запуске.
  • Локальные технические журналы: результаты синхронизации и сообщения об ошибках; они могут содержать служебные сведения о задачах и событиях.

2. Для чего используются данные

Только для создания и обновления календарных событий из задач владельца, предотвращения дублей и диагностики работы синхронизатора. Данные Google Calendar API не используются для рекламы, продажи данных, построения рекламных профилей или обучения обобщённых моделей искусственного интеллекта.

3. Где хранятся и кому передаются данные

Задачи, токены и техническое состояние синхронизации хранятся локально на компьютере владельца. Созданные события хранятся в выбранном Google Календаре. Название задачи, её время и служебная ссылка передаются Google Calendar API по HTTPS. Полное хранилище Obsidian в Google Calendar не передаётся.

Синхронизатор может отправлять владельцу технические уведомления о сбоях и восстановлении через Telegram. Это уведомления о работе сервиса, а не публикация календаря. Отдельные функции личного ассистента, резервное копирование и синхронизация самого хранилища, если владелец их использует, являются отдельными процессами.

Этот публичный сайт размещён на GitHub Pages. Личные задачи, события, журналы и токены сюда не загружаются. На страницах нет собственных форм входа, аналитических скриптов или рекламных трекеров. GitHub и Google могут обрабатывать технические данные обращений к своим сервисам по собственным политикам.

4. Разрешения и безопасность

Google OAuth используется с согласия владельца. Текущая версия запрашивает область доступа Google Calendar, позволяющую управлять календарями; фактически синхронизатор читает связанные события, создаёт и обновляет их. Автоматическое удаление событий при завершении или исчезновении задачи не выполняется.

Пароль Google приложению не передаётся. OAuth-токены не публикуются в репозитории и не должны отправляться в переписку. Владелец отвечает за защиту компьютера, локальных файлов и резервных копий; локальное хранение само по себе не означает шифрование данных.

5. Срок хранения и удаление

Данные остаются в локальном хранилище и Google Календаре до удаления владельцем; эта версия не устанавливает автоматический срок удаления. Для остановки доступа откройте подключения аккаунта Google и отзовите разрешение приложения.

Отзыв доступа прекращает последующие обращения к Google, но не удаляет уже созданные события, локальные заметки и резервные копии. Их нужно удалить отдельно штатными средствами соответствующих приложений. Не удаляйте исходные заметки или календарные события, если хотите лишь временно отключить синхронизацию.

6. Соблюдение правил Google

Использование информации, полученной через Google API, осуществляется в соответствии с Google API Services User Data Policy, включая требования Limited Use. При изменении обработки данных эта политика должна быть обновлена до использования новых функций.

7. Обратная связь

Для вопросов о политике используйте обращения в репозитории приложения. Обращения публичны: не включайте в них персональные данные, задачи, содержимое календаря, пароли или токены.
